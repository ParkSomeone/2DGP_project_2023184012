# `game_framework.py` 작성 안내서

> 이 문서는 강의 PDF 없이 프레임워크 파일을 다른 프로젝트에 복사하고 모드와 연결할 수 있도록 작성했다.

## 역할

`game_framework.py`는 여러 게임 모드를 연결하고, 현재 모드의 이벤트 처리·업데이트·렌더링을 반복하는 작은 실행 프레임워크다. 모드 전환 규칙과 게임 루프를 한곳에서 관리하므로 각 모드는 자기 화면과 상태에 집중할 수 있다.

## 모드가 제공할 함수

프레임워크는 현재 모드 모듈에서 아래 함수를 이름으로 찾아 호출한다.

| 함수 | 역할 |
|---|---|
| `init()` | 모드 진입 시 객체와 리소스 초기화 |
| `handle_events()` | 키보드·마우스·창 종료 등 입력 처리 |
| `update()` | 게임 상태와 객체 갱신 |
| `render()` | 현재 화면 그리기 |
| `finish()` | 모드를 떠날 때 리소스와 월드 정리 |
| `pause()` | 다른 모드가 위에 올라갈 때 일시 정지 처리 |
| `resume()` | 위의 모드가 닫혀 이 모드로 돌아올 때 재개 처리 |

현재 프레임워크는 `push_mode()`에서 현재 모드의 `pause()`를, `pop_mode()`에서 복귀 모드의 `resume()`을 호출한다. 따라서 호출될 수 있는 모드에서는 두 함수가 반드시 정의되어 있어야 한다. 기능이 없으면 `pass`로 둔다.

## 모드 스택과 전환 함수

실습 프레임워크는 모드 모듈을 리스트 스택에 보관한다. 스택의 마지막 요소가 현재 활성 모드다.

- `run(start_mode)`: 시작 모드를 등록하고 메인 루프를 실행한다.
- `change_mode(mode)`: 현재 모드를 `finish()`한 뒤 제거하고 새 모드를 `init()`한다. 이전 모드로 돌아오지 않는다.
- `push_mode(mode)`: 현재 모드의 `pause()`를 호출하고 새 모드를 쌓는다. 예: 게임 화면 위에 일시정지 화면을 띄우는 경우.
- `pop_mode()`: 현재 모드를 `finish()`하고 제거한 뒤, 이전 모드가 있으면 `resume()`한다.
- `quit()`: 루프 종료를 요청한다. 루프를 빠져나온 뒤 남은 모드를 정리한다.

## 루프 구성

```python
while running:
    stack[-1].handle_events()
    stack[-1].update()
    stack[-1].render()
```

현재 실습본은 초기화를 수행한 뒤 루프를 `try/finally`로 감싸고, 종료 시 스택의 모든 모드에서 `finish()`를 호출한다. 이 파일은 `time` 표준 라이브러리만 사용하므로 그래픽 라이브러리와 독립적이지만, 모드는 아래 계약을 지켜야 실행된다.

```python
def init(): pass
def handle_events(): pass
def update(): pass
def render(): pass
def finish(): pass
def pause(): pass
def resume(): pass
```

콜백 함수는 인자 없이 호출된다. `run()`에는 이 함수들을 가진 모듈을 전달한다. `draw()`가 아니라 정확히 `render()`를 제공해야 한다.

## 프레임 시간 (LEC16)

시간을 고려하지 않고 매 프레임 `x += 5`처럼 이동시키면 컴퓨터 성능과 장면 복잡도에 따라 실제 속도가 달라진다. LEC16 실습본은 `time.time()`으로 프레임 경과 시간(초)을 재서 모듈 전역 변수 `frame_time`에 저장한다.

```python
distance = speed_in_pixels_per_second * game_framework.frame_time
x += direction * distance
```

애니메이션도 초당 프레임 수(`frames_per_second`)에 경과 시간을 곱해 진행한다. 따라서 캐릭터와 애니메이션 모두 `frame_time`을 사용해야 실행 속도 변화에도 동작이 일관된다. 프레임 시간은 0이 될 수 있으므로 FPS를 계산할 때는 0으로 나누지 않도록 보호한다. 현재 LEC16 코드는 측정값을 직접 나누므로 확장 시 이 경계를 보완한다.

## 다른 프로젝트에 복사하기

1. `game_framework.py`를 프로젝트의 Python 모듈 경로에 둔다. 시작 모드를 import하는 `main.py`와 모드 파일도 같은 폴더에 두는 구성이 간단하다.
2. 프레임워크는 표준 라이브러리 외에는 의존하지 않는다. 다만 그래픽 모드가 사용하는 라이브러리(이 예제의 경우 `pico2d`)는 별도로 준비해야 한다.
3. 모드에 `init`, `handle_events`, `update`, `render`, `finish`, `pause`, `resume` 함수가 있는지 확인한다.
4. 모드 전환 대상 모듈을 import하고, 모듈 간 순환 import가 생기지 않도록 의존 방향을 정리한다.
5. 모드 초기화 실패나 루프 중 예외 상황에서도 `finish()`가 안전하게 호출될 수 있도록, 아직 생성되지 않은 리소스를 정리 함수에서 참조하지 않게 한다.

### 이식 시 개선할 점

- 현재 구현은 `time.time()`을 사용한다. 시스템 시계가 조정될 수 있는 환경에서 프레임 경과 시간을 측정하려면 시작 시각과 매 프레임 측정에 `time.perf_counter()`를 일관되게 사용하는 편이 안전하다.
- `frame_rate = 1.0 / frame_time`는 프레임 시간이 0일 때 예외가 난다. FPS가 필요할 때는 `frame_time > 0`인 경우에만 계산한다. FPS 출력이 필요 없으면 계산하지 않아도 된다.
- 초기화가 실패했을 때도 `finally`가 실행될 수 있도록 시작 모드의 `init()` 호출도 보호 구문 안에 두는 것이 좋다. 정리 함수는 일부 초기화만 완료된 상태에서도 안전해야 한다.
- 모드 전환을 한 프레임 안에서 여러 차례 요청하지 않는다. 현재 프레임워크는 활성 스택 맨 위의 모드를 즉시 바꾸므로, 이벤트 처리에서 전환 후 반환하는 규칙을 사용한다.

## 작성 규칙과 주의점

- 모드는 클래스 인스턴스가 아니라 모듈로 전달하는 현재 실습 패턴을 따른다.
- 모드 함수 이름과 호출 순서는 프레임워크와 일치시킨다. `render()`와 `draw()`처럼 이름을 혼용하지 않는다.
- `change_mode()`와 `push_mode()`는 의미가 다르다. 일시정지처럼 이전 상태를 보존해야 하는 경우에만 `push_mode()`를 쓴다.
- 프레임워크가 `run()`을 다시 호출할 수 있도록 시작 시 스택·실행 상태·시간 변수를 초기화한다.
- 모드가 예외로 종료되더라도 정리 콜백이 실행되도록 종료 경로를 유지한다.
- 여러 모드가 `game_world`를 공유한다면 `finish()`에서 해당 모드가 소유한 객체와 리소스를 정리한다.

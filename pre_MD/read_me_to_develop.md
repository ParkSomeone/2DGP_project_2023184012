개발언어는 python이다.
모든개발은 pico2d모듈을 기반한다.
소스코드는 sorce디렉터리에 위치한다.
이미지파일은 image디렉터리에 위치한다.
(없는 디렉터리는 추가예정이다.)
출력화면 비율은 16:9이다.

모든 개발은 절차적 개발단계를 통해 진행한다.
모든 개발md파일 생성시 개발단계를 생성하고, 단계가 끝나면 메세지를 커밋하라는 내용을 기입한다.
커밋메세지의 양식은 다음과 같으며, 한글로 작성한다.
"(개발MD파일명)_(개발단계)_(개발내용)"

게임 내에서 진행하는 루프들을 모드라고 정의한다.
게임의 루프 즉, 모드의 관리는 게임프레임워크에서 진행한다.
프레임워크 코드는 framework.py로 존재할 예정이다.

모드를 종합한 md파일은 game_mode_flow.md이고, 각 모드마다 md파일이 존재한다.

이 프로젝트를 구성하는 각 객체마다 파일을 생성해, 클래스로 관리한다.
객체와 객체의 속성을 정리한 md파일은 object.md에 정리한다.
객제를 관리하는 객체는 game_world로 한다.

객체의 상태는 transitions 모듈로 관리하고, from transitions import Machine로 import하며, 다이어그램을 기반으로 구성한다.

======AI보안점============================

- 작업을 시작하기 전에 저장소의 실제 폴더와 파일을 확인한다. 문서에 적힌 경로와 실제 경로가 다르면 임의로 이름을 변경하지 말고 차이를 보고한다. 특히 `sorce`가 의도된 폴더명인지 확인하고 문서 간 표기를 통일한다.
- `mode.md`, 각 모드 문서, `object.md`, 상태 다이어그램의 위치와 작성 순서를 확인한다. 해당 자료가 없거나 내용이 서로 충돌하면 추측으로 구현하지 말고 사용자에게 확인한다.
- 게임 프레임워크는 모드의 전환과 실행 흐름을 관리하고, `world`는 게임 객체의 생성·보관·갱신·삭제를 담당하도록 역할을 구분한다. 기존 구조가 다르면 먼저 구조를 확인하고 변경 범위를 보고한다.
- 독립적인 상태와 동작이 있는 요소를 객체로 만들고 클래스로 관리한다. 단순 데이터나 밀접하게 연관된 기능까지 불필요하게 파일과 클래스로 나누지 않는다.
- 개발 환경은 저장소에 설정된 Python, pico2d, transitions 버전을 우선 확인한다. 버전이나 의존성이 정해져 있지 않으면 임의로 업그레이드하거나 새 의존성을 추가하지 말고 사용자에게 확인한다.
- 각 개발 단계에는 구현 범위와 완료 조건을 정하고, 단계가 끝나면 변경 내용과 실행·테스트 결과 및 미해결 사항을 보고한다. 테스트하지 않은 항목을 완료된 것으로 표시하지 않는다.
- 커밋 메시지는 `"(개발MD파일명)_(개발단계)_(개발내용)"` 형식의 한글로 제안한다. 사용자 확인 없이 커밋하지 않는다.
- 화면 비율 16:9를 유지하는 방식과 기준 해상도를 확인한다. 다른 창 크기에서 화면을 늘릴지, 비율을 유지할지, 레터박스를 사용할지 정해지지 않았다면 임의로 선택하지 말고 확인한다.
- 비밀정보나 개인 정보를 코드·문서·로그에 기록하거나 외부에 전송하지 않는다. 기존 파일을 수정할 때는 요청 범위 밖의 변경을 보존하고, 불필요한 삭제나 덮어쓰기를 하지 않는다.

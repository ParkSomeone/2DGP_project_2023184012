이 파일를 통해 구현할 내용은 다음과 같다.

//작성 조건: 이 파일은 이벤트 송출, 소모를 구현할수 있다고 가정한것이다. 충돌판정을 하는 객체는 실질적으로 변수가 변하는 객체이다.

발판과 몬스터의 이동속도, 배경의 이동속도, 플레이어의 피격시x축 변화 속도는 같다.

스테이지

게임의 스테이지는 다음과 같은 구조로 이우러져있다.

배경, 발판, 몬스터, 보스, 플레이어가 존재한다.

스테이지 모드에서 2분이 지나면 스테이지 생존 성공으로, 스테이지 선택 모드로 전환된다.

배경

배경은 가로로 반복하며, 우측으로 이동한다.

발판

발판은 class로 존재하며, 바닥과 같은 판정이 일어난다.

발판을 타일형식으로 이루어져 있으며, 시작, 중앙, 끝 3개의 파일로 구성한다.

바닥과 발판을 포함한 층은 3개로 이루어진다.

발판의 길이는 랜덤으로 한다.

발판은 왼쪽에서 오른쪽으로 일정한 속도로 이동한다.

몬스터

몬스터는 바닥과 발판위에 존재한다.

몬스터의 이동은 왼쪽에서 오른쪽이고, 이동속도는 발판의 속도와 같다.

(즉 발판 위에서 움직이지 않은것처럼 보여야 한다.)

몬스터는 체력이 있고, 체력이 0이되면 사망 이펙트 후 플레이어에게 몬스터 처치 이벤트를 넘긴다.

몬스터와 플레이어가 부딪치면 플레이어는 약간의 경직(0.1초)상태가 된다.

보스

보스는 오른쪽에 존재한다.

게임 내에서 좌표이동은 하지 않는다.

보스의 체력이 0이하가 되면 게임 클리어모드로 넘어간다.

플레이어

키보드 좌우키로 이동하고, 스페이스바로 점프한다. 점프력은 층과 층 사이 간격의 1.3배이다액티브 스킬은 w,e,r로 발동한다. 회복아이템 사용은 q키이다.

플레이어가 바라보는 방향은 액티브스킬에서 조준방향이 플레이어의 오른쪽인 경우를 제외하면 항상 외쪽을 바라본다.

플리이어는 일정시간마다 자동으로 공격을 한다.

패시브스킬은 쿨타임을 확인하고 0이면 발동한다.

액티브스킬은 키(w,e,r)을 누를시, 쿨타임이 0이면 발동한다.

스킬은 발동후 쿨타임이 초기화된다.

물약은 q키를 누를시, 개수가0보다 크면 사용한다.

물약은 최대체력의 50% 회복한다.

몬스터와 플레이어가 부딪치면 플레이어의 체력으 소폭 감소하고, 경직(0.05초)된다.경직시 발판과 같은속도로 오른쪽으로 이동한다.

보스와 부딪치면 플레이어의 체력을 0으로 만든다.

플레이어의 체력이 0이면 게임오버모드로 전환된다.

보물상자와 충돌했으면 강화가능수치가 2 오른다.

경험치(A)가 레벨당 설정된 값(B)을 넘기면 경험치는 A-B가 되며, 레벨이 1오른다.

레벨이 오르면 강화가능수치가 1 오른다.

강화가능수치가 0보다크면 1감소하고 강화모드로 전한된다.

AI 개발 지시사항 - 스테이지 모드만 구현

목표

이 문서를 입력으로 AI에게 개발을 요청할 때는 스테이지 모드만 구현한다. 기존 프로젝트의 구조와 코딩 규칙을 먼저 확인하고, 아래 범위와 완료 조건을 만족하는 데 필요한 변경만 한다.

구현 범위

- 스테이지 모드의 배경, 바닥과 발판, 몬스터, 보스, 플레이어를 구현한다.
- 스테이지 모드에서 필요한 이동, 충돌, 체력 변화, 공격 및 피격, 경험치·레벨·강화 가능 수치, 물약과 스킬 동작을 구현한다.
- 스테이지 생존 성공, 플레이어 사망, 보스 처치, 강화 진입 등 다른 모드가 처리해야 하는 결과는 프로젝트에 이미 있는 이벤트나 모드 전환 규약으로 알린다.
- 이벤트 시스템과 충돌 시스템이 이미 있다면 이를 재사용한다. 충돌 처리로 상태가 변하는 객체만 충돌 판정 대상에 포함한다.

구현하지 않을 범위

- 로딩, 타이틀, 옵션, 캐릭터 선택, 스테이지 선택, 강화 화면, 일시정지 화면 및 클리어·게임오버 화면 자체는 구현하지 않는다.
- 위 화면의 전환 로직이나 스테이지 선택 맵을 새로 만들지 않는다. 다만 스테이지 모드에서 필요한 결과 이벤트는 기존 규약으로 전달한다.
- 이 문서에 없는 게임 규칙이나 외부 라이브러리를 임의로 추가하지 않는다.

개발 절차

1. 저장소에서 소스 디렉터리, 실행 진입점, 게임 모드·이벤트·충돌 처리 방식, 이미지 자산과 기존 개발 문서를 확인한다. 문서의 클래스 이름이나 동작을 기존 구조에 그대로 맞출 수 없다면 구현 전에 차이와 필요한 결정을 보고한다.
2. 스테이지 모드의 진입·갱신·입력·그리기·종료 경계를 기존 모드 규약에 맞춰 정한다. 다른 모드에 의존하는 결과는 화면을 직접 구현하지 말고 이벤트 또는 기존 인터페이스로 전달한다.
3. 배경과 바닥·발판 이동, 플레이어 이동·점프, 몬스터와 보스의 배치 및 이동을 구현한다.
4. 충돌, 공격·피격, 체력과 사망, 경험치·레벨·강화 진입, 스킬·물약 사용을 구현한다.
5. 스테이지 종료 조건과 결과 이벤트를 연결하고, 기존 테스트 방식으로 동작을 검증한다. 테스트가 없다면 재현 가능한 수동 검증 절차와 확인 결과를 보고한다.
6. 각 개발 단계가 끝날 때마다 변경 사항을 요약하고 사용자에게 커밋을 요청한다. 커밋을 요청할 때 메시지는 "(개발MD파일명)_(개발단계)_(개발내용)" 형식의 한글로 제안한다. 사용자 확인 없이 커밋하지 않는다.

완료 조건

- 스테이지 모드에 진입하면 배경, 바닥·발판, 플레이어, 몬스터와 보스가 기존 프로젝트의 방식으로 갱신되고 그려진다.
- 플레이어의 입력, 점프, 발판 착지, 몬스터·보스 충돌 및 공격에 따른 상태 변화가 확인된다.
- 체력 0, 보스 체력 0 이하, 생존 시간 종료, 강화 진입 조건이 각각 해당 결과 이벤트를 한 번만 전달한다.
- 프로젝트의 기존 실행·테스트 절차가 유지되고, 구현 범위 밖 화면이나 모드 동작은 변경되지 않는다.
- 완료된 테스트와 미해결 사항을 요약하며, 확인하지 못한 동작을 완료된 것처럼 보고하지 않는다.

구현 전에 확인할 규칙 충돌 및 미정 사항

- 이 문서에는 배경이 오른쪽으로 이동한다고 적혀 있지만, 발판과 몬스터의 이동 설명 및 실제 화면에서의 상대 이동 방향이 모호하다. 기존 프로젝트의 좌표계와 화면 연출을 확인하고, 서로 모순되면 사용자에게 확인한다.
- 자동 공격의 주기·대상 선택, 스킬별 효과와 수치, 몬스터·보스 생성 규칙, 층별 발판 배치와 무작위 길이 범위가 정해져 있지 않다. 기존 코드나 자산에서 근거를 찾을 수 없으면 임의의 값을 게임 규칙으로 확정하지 말고 필요한 질문을 먼저 한다.

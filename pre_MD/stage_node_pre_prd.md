# 스테이지 노드 개발 문서 (`stage_node_pre_prd.md`)

## 목적

추격 스테이지의 생존 시간이 끝났을 때 스테이지 선택 모드로 이동하고, 노드 기반 분기형 맵에서 다음 스테이지를 선택하는 기능의 개발 범위와 연동 규칙을 정의한다.

이 문서에서 **스테이지 노드**는 스테이지 선택 화면에 표시되는 맵상의 선택 지점을 뜻한다. 노드 맵은 스테이지 선택 모드의 책임이며, 추격 스테이지 모드에 노드 선택 UI나 맵 전환 로직을 추가하지 않는다.

## 저장소에서 확인된 기준

- 실제 Python 소스 디렉터리는 문서에 자주 적힌 `sorce`이며, 실행 진입점은 `sorce/main.py`다.
- 현재 시작 모드는 `sorce/main.py`가 지정하는 `play_mode`다. `game_framework.change_mode(mode)`는 현재 모드를 종료하고 새 모드를 시작한다.
- 추격 모드는 120초가 지나면 `play_mode.consume_events()`에서 소비할 수 있는 `{"type": "survived"}` 결과 이벤트를 한 번 기록한다.
- 기존 스테이지 구현은 `survived`, `player_died`, `boss_defeated` 등의 결과를 이벤트로 제공한다. 스테이지 선택은 아직 구현되어 있지 않다.
- 게임 기획은 노드 기반 분기형 맵을 정의한다. 후속 노드가 없는 맵은 보스 스테이지이며, 후속 스테이지가 있는 선택은 추격 스테이지로 이어진다.
- 기존 `stage_mode_pre_prd.md`는 스테이지 모드만 구현 대상으로 삼으며 스테이지 선택 화면과 맵 구현은 제외한다. 이 문서는 그와 분리된 스테이지 선택 모드 개발 규약이다.

## 목표 흐름

```text
추격 스테이지 진행
    ├─ 플레이어 사망 ───────────────> 게임오버 결과 전달 (기존 규약)
    ├─ 보스 처치 ───────────────────> 게임 클리어 결과 전달 (기존 규약)
    └─ 120초 생존 성공 (`survived`)
             └─> 스테이지 선택 모드
                    ├─ 후속 노드가 있는 스테이지 선택 ─> 추격 스테이지
                    └─ 후속 노드가 없는 보스 노드 선택 ─> 보스전 스테이지
```

2분 생존은 **현재 추격 스테이지의 클리어/생존 성공**이며, 전체 게임의 최종 클리어와 구분한다. 생존 성공 직후에는 기존 전환 규약을 통해 스테이지 선택 모드로 이동한다. 최종 보스 처치에 따른 전체 게임 클리어 화면은 이 기능의 범위에 포함하지 않는다.

## 구현 범위

- 스테이지 선택 모드의 진입, 초기화, 입력 처리, 갱신, 그리기, 종료 인터페이스
- 기존 기획의 노드 기반 분기형 스테이지 맵 표현
- 선택 가능한 노드와 선택할 수 없는 노드의 상태 표현 및 입력 차단
- 선택 결과에 따라 추격 스테이지 또는 보스전 스테이지로 이동하도록 기존 모드 프레임워크와 연결
- 추격 스테이지의 `survived` 결과를 스테이지 선택 모드 진입 신호로 연결
- 모드 전환 사이에서 현재 진행 노드와 선택 결과를 보존하는 방법을 기존 프로젝트 구조에 맞춰 결정

## 구현하지 않을 범위

- 추격 스테이지의 플레이, 타이머, 충돌, 적·발판 생성 및 결과 이벤트 내부 로직
- 보스전 자체와 보스전 전투 규칙
- 타이틀, 로딩, 옵션, 캐릭터 선택, 강화, 게임오버 및 전체 게임 클리어 화면
- 기획에 없는 노드 수, 맵 배치, 경로 잠금 규칙, 보상, 스테이지별 전투 수치
- 새로운 그래픽·이벤트 프레임워크 또는 외부 의존성 추가

## 노드와 진행 데이터 계약

구현 시 노드 데이터는 기존 프로젝트의 자료 구조를 우선 사용한다. 별도 구조가 꼭 필요한 경우 아래 정보가 표현되어야 하며, 이름과 저장 위치는 구현 전 기존 코드와 대조한다.

| 정보 | 의미 |
|---|---|
| 노드 ID | 맵에서 스테이지를 식별하는 고유 키 |
| 노드 종류 | 추격 스테이지 또는 보스 스테이지 |
| 후속 노드 | 이 노드의 선택 이후 이어질 수 있는 노드 ID 목록 |
| 선택 가능 상태 | 현재 진행 경로에서 선택할 수 있는지 나타냄 |

기획상 후속 스테이지가 있는 선택은 추격 스테이지로 연결되고, 후속 노드가 없는 종착 노드는 보스 스테이지다. 실제 맵의 시작 노드, 분기 수, 연결 데이터, 노드 해금 조건은 확정되어 있지 않다. 근거가 기존 코드나 승인된 자료에 없으면 임의로 확정하지 말고 질문한다.

선택 화면에서 현재 진행 경로와 선택 가능 상태를 구분해 표현한다. 선택 불가능한 노드의 시각적 표현, 선택 입력 방식(마우스/키보드), 선택 확인 또는 취소 방식은 기존 UI 패턴이 확인되지 않으면 결정 사항으로 남긴다.

## 모드 연동 규칙

1. 추격 모드가 `survived` 결과를 제공하면 이를 소비하고, `game_framework.change_mode(stage_select_mode)`를 통해 스테이지 선택 모드로 이동한다.
2. 결과 이벤트는 한 번만 처리한다. 같은 이벤트를 반복 소비하거나 렌더링할 때마다 모드 전환을 요청하지 않는다.
3. 모드 전환 시 프레임워크가 현재 모드의 `finish()`를 부르므로, 다음 노드 선택에 필요한 진행 정보는 추격 모드의 임시 전역 변수에만 의존하지 않도록 한다. 저장소에 이미 있는 게임 진행 상태 소유자를 우선 사용한다.
4. 선택된 노드에 후속 연결이 있으면 그 연결에 해당하는 추격 스테이지를 시작한다. 선택된 노드가 종착 보스 노드이면 보스전 모드를 시작한다.
5. 모드 이름, import 경로, 인자 전달 또는 공유 상태 방식은 실제 대상 모드가 추가될 때 프레임워크와 대조해 결정한다. 아직 존재하지 않는 모듈을 전제로 실행 가능한 것으로 보고하지 않는다.
6. 새 모드는 프레임워크 계약에 맞춰 `init()`, `handle_events()`, `update()`, `render()`, `finish()`, `pause()`, `resume()`를 제공한다. 사용하지 않는 콜백은 기존 패턴에 따라 비워 둔다.

## 미정 사항

다음 항목은 현재 문서만으로 완성된 스테이지 선택 UI와 맵 데이터를 만들 수 없으므로, 구현 전 기존 자료를 확인하고 결정한다.

- 시작 노드와 전체 스테이지 노드·연결 데이터
- 노드의 화면 배치, 배경, 이미지/아이콘 자산 및 시각 스타일
- 플레이어가 노드를 선택하는 입력 방식과 선택 확인 동작
- 선택 가능한 노드의 해금 규칙과 이전 경로 표시
- 스테이지 진행 데이터의 소유자 및 재시작/새 게임 시 초기화 시점
- 보스 노드 진입 후 보스전에서 복귀 또는 재시작하는 규칙
- 생존 성공 후 즉시 맵으로 이동할지, 별도의 성공 연출/확인 화면을 거칠지

위 항목은 기획이나 기존 UI 구현에서 근거가 발견되지 않으면 추측으로 고정하지 말고 사용자 확인을 받는다.

## 개발 단계 및 완료 조건

### 1단계: 구조와 맵 데이터 확인

- 모드 프레임워크, `survived` 이벤트 소비 방식, 기존 이미지·UI 자산, 스테이지 관련 기획을 확인한다.
- 노드 연결 데이터와 진행 상태를 둘 위치를 확정하고, 미정 항목을 정리한다.
- **완료 조건:** 실제 모드 전환 API와 진행 상태 소유자가 확인되고, 구현에 필요한 맵 데이터가 준비되거나 미정으로 명시된다.

### 2단계: 노드 맵 표현 및 선택

- 스테이지 선택 모드의 필수 콜백과 노드의 표시·선택 가능 상태를 구현한다.
- 확정된 맵 연결 데이터에 따라 선택 입력을 제한한다.
- **완료 조건:** 선택 가능한 노드가 구분되어 표시되고, 선택 불가능한 노드는 선택 결과를 만들지 않는다.

### 3단계: 생존 결과와 선택 스테이지 연결

- 추격 모드의 `survived` 결과를 한 번만 처리해 스테이지 선택 모드로 이동한다.
- 선택 노드의 연결 여부와 노드 종류에 맞춰 추격 또는 보스전 모드로 이동한다.
- **완료 조건:** 120초 생존 성공 후 맵이 열리고, 각 노드 선택이 올바른 대상 모드로 연결되며, 사망/보스 처치 결과가 생존 성공으로 잘못 처리되지 않는다.

### 4단계: 진행 상태 유지 및 검증

- 모드 전환 후 선택/진행 경로가 보존되는지, 새 게임 초기화 시 올바르게 초기화되는지 검증한다.
- 기존 테스트를 실행한다. 테스트가 없다면 재현 가능한 수동 검증 절차와 실제 확인 결과를 보고한다.
- **완료 조건:** 노드 선택과 모드 전환이 반복 진입에서도 일관되고, 미구현 대상 모드나 미확인 동작은 완료로 표시되지 않는다.

각 개발 단계가 끝나면 변경 사항, 검증 결과 및 미해결 사항을 보고하고 사용자에게 커밋을 요청한다. 커밋 메시지는 한글로 다음 형식을 제안한다.

```text
(stage_node_pre_prd)_(개발단계)_(개발내용)
```

사용자 확인 없이 커밋하지 않는다.

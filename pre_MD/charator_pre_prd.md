# 캐릭터 구현 개발 문서 (`charator_pre_prd.md`)

## 목적

이 문서는 `기획.md`를 바탕으로 플레이어 캐릭터의 구현 범위와 규칙을 정리한다. 캐릭터의 입력, 이동, 피격, 체력, 경험치·레벨, 물약, 액티브·패시브 스킬 동작을 기존 게임 구조에 연결한다. 캐릭터가 속한 스테이지, 강화 화면, 게임오버 화면 등 다른 모드 자체는 구현하지 않는다.

`기획.md`에서 수치가 언어로 표현된 항목은 조정 가능한 기획값이다. 아래에 별도 확정값으로 적지 않은 수치나 효과를 구현자가 임의로 게임 규칙으로 확정하지 않는다.

## 구현 전 저장소 확인

1. 저장소의 실제 소스 디렉터리, 실행 진입점, 프레임워크, 게임 월드, 이벤트·충돌 처리 방식과 이미지 자산을 확인한다.
2. `read_me_to_develop.md`의 `sorce`·`framework.py`와 다른 문서의 경로·파일명이 다르면 경로를 임의로 고치지 말고 실제 구조와 차이를 보고한다.
3. `object.md`, `class_state.md`, `game_mode_flow_pre.md`, `stage_mode_pre_prd.md`의 캐릭터 속성·상태·호출 규약이 서로 다르면 충돌을 정리하고 필요한 결정을 확인한다.
4. 프로젝트에 정해진 Python, pico2d, transitions 환경을 우선 사용한다. 설정이 없으면 버전이나 의존성을 임의로 추가·업그레이드하지 않는다.
5. 캐릭터 이미지와 애니메이션 자산이 없으면 임의의 경로나 프레임 구성을 전제로 완성 처리하지 않는다. 필요한 자산 및 대체 방식은 미해결 사항으로 보고한다.

## 캐릭터 책임과 범위

캐릭터는 자신의 위치, 이동, 체력, 피격 상태, 경험치·레벨, 물약 수, 스킬별 쿨타임을 관리한다. 프로젝트에 이미 있는 월드·입력·충돌·이벤트 방식을 사용하고, 중복되는 관리 기능을 새로 만들지 않는다.

### 구현 범위

- 추격 모드에서 기본적으로 왼쪽을 향해 달리는 캐릭터 애니메이션
- 좌우 입력에 따른 캐릭터 위치 이동
- 몬스터 및 보스와의 충돌 결과 반영
- 체력, 피격 경직, 무적 시간과 사망 결과 통지
- 몬스터 처치 경험치에 따른 레벨 및 강화 가능 수치 갱신
- Q 물약 사용
- W/E/R 액티브 스킬의 입력, 조준 방향과 쿨타임
- 3개 패시브 스킬의 시간 기반 발동
- 상태 전이와 캐릭터 갱신·그리기 인터페이스 연결

### 구현하지 않을 범위

- 추격 스테이지, 보스, 몬스터, 발판, 보물상자 및 강화 화면 자체
- 타이틀, 캐릭터 선택, 스테이지 선택, 게임오버·클리어 화면
- 기획에 없는 스킬 효과, 기본 공격 방식, 적의 공격 규칙 및 UI
- 프로젝트에 없는 별도의 입력·충돌·이벤트 프레임워크

다른 객체가 발생시킨 충돌·처치 정보를 캐릭터에 전달할 때에는 기존 이벤트/API를 우선 사용한다. 외부 규약이 없으면 임의의 모드 전환을 직접 호출하지 말고, 구현 전에 연결 방법을 보고한다.

## 상태와 데이터

`class_state.md`의 플레이어 속성 초안은 `image`, `skill_list`, `x`, `y`, `speed`, 점프에 필요한 변수다. 실제 프로젝트의 `object.md` 및 코드와 대조해 필요한 항목만 사용한다. 중복된 값이나 소유권이 불명확한 변수를 늘리지 않는다.

캐릭터의 행동 상태는 프로젝트 규칙대로 `from transitions import Machine`의 `Machine`을 이용해 관리한다. `game_mode_flow_pre.md`에서 추격 모드는 2분 경과, 보물상자 획득, 레벨업, 보스 접촉, 보스 체력 소진 등의 결과에 따라 다른 모드로 전환된다. 해당 전환이 발생하기 전까지 캐릭터의 기본 행동 상태는 왼쪽을 향해 달리는 `RUN`이다. 좌우 키 입력은 위치 이동을 제어하며, 별도 정지 규칙이 정해지지 않은 한 입력이 없어도 달리기 애니메이션은 계속된다. 액티브 스킬을 마우스로 조준하는 동안에는 `AIM` 상태로 전환하고, 추격 모드의 2분 카운터 진행률과 이동 속도를 각각 평상시의 0.5배로 낮춘다.

```text
 [RUN] ── 조준 시작 ──> [AIM] ── 발동 또는 취소 ──> [RUN]
   │                     │
   └── 피격(무적 아님) ──┴──> [HITSTUN] ── 경직 종료 ──> [RUN]

 [RUN / AIM / HITSTUN] ── 체력 0 또는 보스 접촉 ──> [DEAD]
 [DEAD]는 종료 상태이며 다른 행동 상태로 돌아가지 않는다.
```

### 상태별 동작

| 상태 | 진입 및 유지 조건 | 상태 중 처리 | 종료 및 전이 |
|---|---|---|---|
| `RUN` (왼쪽 달리기) | 추격 모드에서 생존 상태로 시작하거나 피격 경직이 끝남 | 왼쪽을 향한 달리기 애니메이션을 반복한다. 좌우 입력은 캐릭터 위치에 반영하되, 걷거나 서는 애니메이션으로 자동 전환하지 않는다. 이동 속도·화면 경계는 미정 규칙을 따른다. | 유효한 몬스터 피격 시 `HITSTUN`; 체력 0 또는 보스 접촉 시 `DEAD`. 모드 전환 시 애니메이션 진행은 프레임워크의 모드 정지·복귀 규약을 따른다. |
| `AIM` (조준) | 생존 중 사용 가능한 액티브 스킬을 사용하기 위해 마우스 조준을 시작함 | 마우스 위치로 조준 방향을 정한다. 추격 모드의 2분 경과 카운터 진행과 게임 내 이동 속도에 0.5 배율을 적용한다. | 스킬 발동 또는 조준 취소 시 `RUN`; 유효한 몬스터 피격 시 `HITSTUN`; 체력 0 또는 보스 접촉 시 `DEAD`. 조준 중단 후 시간·이동 배율은 1.0으로 복귀한다. |
| `HITSTUN` (피격 경직) | 무적 상태가 아닌 때 몬스터 피격이 유효하게 적용됨 | 기획상 경직 시간은 약 0.05~0.1초다. 피해 및 1.5초 무적 타이머를 적용한다. 경직 중 이동·달리기 애니메이션 처리 방식은 확인 전까지 확정하지 않는다. | 경직이 끝나면 `RUN`; 체력 0 또는 보스 접촉 시 `DEAD` |
| `DEAD` (사망) | 체력이 0 이하가 되거나 추격 스테이지에서 보스와 접촉함 | 사망 결과를 기존 이벤트/API로 한 번만 알린다. 추가 이동·스킬 사용·물약 사용·피해 적용을 막는다. | 종료 상태. 게임오버 화면이나 모드 전환 자체는 이 캐릭터 문서의 구현 범위가 아니다. |

기획에는 달리기 애니메이션 중 좌우 키 입력 시 캐릭터가 어느 방향을 향하는지 구체화되어 있지 않다. 캐릭터는 액티브 스킬 조준 시를 제외하면 왼쪽을 바라본다는 규칙에 따라, 좌우 이동 입력이 달리기 애니메이션의 바라보는 방향을 바꾸지는 않는 것으로 한다. 실제 좌표 이동 방향과 화면 경계 동작은 별도의 이동 규칙이 확정될 때 정한다.

### 상태와 별도로 관리하는 동작·타이머

- **무적:** 피격 후 약 1.5초 동안의 방어 시간이다. 행동 상태와 겹쳐 유지될 수 있는 타이머로 취급한다. 무적 중 추가 몬스터 피해 및 경직 전이는 적용하지 않는다. 무적 만료만으로 `RUN` 상태를 바꾸지 않는다.
- **조준 시간 배율:** `AIM` 동안 추격 모드의 2분 경과 카운터와 게임 내 이동 속도에 각각 0.5를 곱한다. 상태가 끝나면 두 배율을 1.0으로 복구한다. 게임 시간과 이동 속도를 모두 늦추는 것은 명시된 규칙이며, 스킬 쿨타임·애니메이션·무적·경직 타이머까지 느리게 할지는 별도로 정해지지 않았으므로 임의로 적용하지 않는다.
- **액티브 스킬:** W/E/R은 액티브 스킬 선택/사용 입력이다. 마우스 조준 중 `AIM`에 머물고, 발동 성공 시 해당 쿨타임을 초기화한다. 스킬 효과, 실제 발동 확정 입력 및 쿨타임 적용 시점이 정해져 있지 않으므로 기존 규약을 확인한다.
- **패시브 스킬:** 3개 스킬의 시간 조건이 충족되면 자동 발동한다. 스킬 효과와 발동 주기는 미정이며, 패시브 발동만을 위해 캐릭터 행동 상태를 바꾸지 않는다.
- **물약:** Q 입력 시 보유량이 있을 때 사용을 요청한다. 물약 사용이 다른 상태를 취소하거나 막는지는 기획에 없으므로 기존 입력 규약을 확인한다.
- **점프:** `class_state.md`에는 점프 변수가 있으나 `기획.md`에는 점프 입력·상태·착지 규칙이 없다. 따라서 위 상태 다이어그램에는 점프 상태를 포함하지 않는다. 점프가 요구되면 승인된 규칙을 확인한 뒤 `JUMP` 및 착지 전이를 추가한다.

상태 전이는 기존 코드의 명명과 애니메이션·이벤트 구조에 맞춰 구현한다. 위 표에서 정하지 않은 입력 우선순위, 동시에 발생한 피격과 사망의 처리, 경직 중 이동 정책은 임의로 결정하지 않는다. 시간은 프레임 횟수가 아닌 프로젝트의 프레임 경과 시간 규약으로 갱신한다.

## 객체 인터페이스와 연동

기존 프로젝트에서 요구하는 캐릭터 클래스명과 모듈명을 따른다. 클래스명·파일명이 정해져 있지 않으면 임의로 다른 모듈을 대량 수정하지 말고 명명안을 보고한다.

스테이지/월드가 요구하는 `update()` 및 `draw()` 등 기존 인터페이스를 제공한다. 입력 이벤트와 충돌 결과는 해당 모드 또는 기존 시스템이 전달하는 구조를 사용한다. 입력 처리, 게임 상태 갱신, 화면 그리기를 한 함수에 섞지 않는다.

시간에 따른 이동·경직·무적·쿨타임은 프로젝트 프레임워크의 프레임 시간 규약을 확인해 처리한다. 프레임 수에 종속된 타이머를 새로 도입하지 않는다. 캐릭터는 화면 전체를 지우거나 다른 모드의 화면을 직접 실행하지 않는다.

## 개발 단계 및 완료 조건

### 1단계: 구조와 캐릭터 계약 확인

- 관련 디렉터리, 자산, 기존 캐릭터/상태/입력/충돌 규약을 확인한다.
- 문서 간 차이와 필요한 결정을 목록으로 남긴다.
- **완료 조건:** 실제 파일·의존성과 사용할 클래스/API가 확인되고, 구현을 막는 미정 사항이 식별된다.

### 2단계: 캐릭터 기본 구조와 이동

- 기존 명명·인터페이스에 맞춰 왼쪽 달리기 애니메이션, 캐릭터 상태와 좌우 이동을 연결한다.
- 상태 머신을 기존 상태 규약에 맞게 구성한다.
- **완료 조건:** 추격 모드에서 왼쪽 달리기 애니메이션이 기본 재생되고, 좌우 입력이 위치 이동으로 정상 전달된다.

### 3단계: 피격·체력·사망

- 몬스터 피격의 피해·경직·무적 처리와 보스 접촉 사망 처리를 연결한다.
- 사망 결과가 중복 통지되지 않도록 한다.
- **완료 조건:** 각 충돌 결과와 무적 시간 동안의 추가 피격 차단을 확인한다.

### 4단계: 경험치·레벨·물약

- 처치 경험치, 레벨업, 강화 가능 수치 및 Q 물약을 기존 시스템에 연결한다.
- 미정 수치는 확인 전까지 임의로 확정하지 않는다.
- **완료 조건:** 경험치 초과분, 레벨 변화, 물약 수량·회복, 강화 결과 전달을 확인한다.

### 5단계: 액티브·패시브 스킬

- W/E/R 입력, `AIM` 상태 진입·종료, 조준 방향, 2분 카운터·이동 속도 0.5 배율, 쿨타임과 3개 패시브의 시간 기반 발동을 연결한다.
- 각 스킬 효과와 밸런스 수치는 승인된 규칙이나 기존 구현 근거가 있을 때만 적용한다.
- **완료 조건:** 사용 가능/쿨타임 중 입력, AIM 진입·발동·취소 및 피격 중단, 조준 좌우 판정, 조준 중 2분 카운터와 이동 속도가 정확히 0.5배인지, 종료 후 1.0배로 복구되는지, 패시브 발동과 타이머 초기화 규칙을 확인한다.

### 6단계: 통합 검증 및 결과 보고

- 기존 테스트를 실행한다. 테스트가 없으면 재현 가능한 수동 검증 절차와 실제 확인 결과를 기록한다.
- 미검증 기능과 남은 기획 결정을 명시한다.
- **완료 조건:** 확인한 항목과 미확인 항목이 구분되어 보고되고, 문서 범위 밖 화면 및 모드가 변경되지 않는다.

각 개발 단계가 끝나면 변경 내용과 테스트 결과를 사용자에게 보고하고 커밋을 요청한다. 커밋 메시지는 한글로 다음 형식을 제안한다.

```text
(charator_pre_prd)_(개발단계)_(개발내용)
```

사용자 확인 없이 커밋하지 않는다.

## 구현 전 확인이 필요한 항목

다음 항목은 기획 문서만으로 구현 규칙을 확정할 수 없다. 기존 코드나 다른 승인된 문서에서 근거를 찾지 못하면 해당 기능을 임의 설계하지 말고 질문한다.

1. 이동 속도, 화면 경계, 좌우 입력에 따른 좌표 이동량 및 배경 스크롤과의 상대 이동
2. 점프의 포함 여부와 입력·점프력·착지 규칙 (`class_state.md`에는 점프 변수가 있으나 `기획.md`에는 동작이 없음)
3. 달리기 애니메이션 자산, 프레임 구성·속도·크기 및 왼쪽을 향한 이미지의 기준 방향
4. 최대 체력 초기값, 몬스터 접촉 피해의 정확한 비율, 물약 회복의 최대 체력 초과 허용 여부
5. 경험치 획득량, 레벨별 필요 경험치, 한 번에 여러 레벨업할 때의 규칙
6. 강화 가능 수치의 사용·소모 시점과 강화 모드로 전달하는 기존 인터페이스
7. 액티브 3종 및 패시브 3종의 구체 효과, 쿨타임/발동 주기, 중복 발동·재사용 규칙
8. AIM 진입 입력, 조준 완료 후 발동 입력, 취소 입력, 쿨타임이 시작되는 시점
9. 0.5 이동 배율을 캐릭터만 적용할지, 배경·발판·몬스터 등 게임 내 모든 이동에 적용할지 여부
10. 피격 경직 중 이동·달리기 모션 처리, AIM 중 피격 시 조준 복구 여부, 연속 피격 및 무적 종료 시 처리
11. AIM 배율을 보스전에도 적용할지 여부와 보스전의 조준 시간 기준
12. 스킬 쿨타임·애니메이션·무적·경직 타이머도 AIM 중 느려지는지 여부
